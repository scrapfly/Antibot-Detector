# Changelog

All notable changes to the Scrapfly Antibot Detector extension are documented in this file.

---

## v2.7

### Fixes
- **JS hooks no longer break strict SPAs (e.g. claude.ai)** — The MAIN-world hook wrapper (`content-main-world.js`) ran detection logic and behavior-altering transforms on *every* call to hooked APIs, though detection is one-shot per target. Reworked the wrapper to be a transparent passthrough while preserving identical detection output (first access still fires exactly one `JS_HOOK_DETECTION` per `detectorId:target`):
  - **One-shot fast path** — Added a per-install `exhaustedHooks` set; once every detector for a target has fired, the wrapper skips the detection path entirely, eliminating per-call overhead on hot APIs (`Performance.prototype.now`, `Window.prototype.getComputedStyle`, `EventTarget.prototype.addEventListener`). Covers non-configurable targets that cannot be uninstalled.
  - **No completion-timer churn** — `scheduleCompletion()` now runs only on genuine new detections, not on every duplicate fire (was `clearTimeout`+`setTimeout` per hot-path call).
  - **Transparent error/return behavior** — Removed the proactive `this===window` rebind and the returned-promise `.catch` re-wrap (preserves promise identity); the context-retry now triggers *only* on a genuine `Illegal invocation` instead of any error, so side-effecting APIs are never silently re-executed and native errors propagate unchanged. Same fix applied to `createBindShim`.
  - **Narrowed global error suppression** — The window `error` handler previously called `preventDefault()` on *any* error attributed to `content-main-world` (swallowing genuine page/API errors); it now only suppresses our own internal `Illegal invocation` noise. Detection-callback and `unhandledrejection`-inspection failures are now logged under `debugMode` instead of silently ignored.
  - **Constructor/namespace targets are no longer wrapped (root cause of the blank page)** — `installHook` now refuses to hook a non-`*.prototype.*` target whose value is a constructor (e.g. `Intl.DateTimeFormat`, `DeviceMotionEvent`, `DeviceOrientationEvent`). Replacing such a constructor with a plain-function wrapper silently dropped its static methods (`Intl.DateTimeFormat.supportedLocalesOf`) and broke `new`/subclassing, throwing during the page's init and leaving strict SPAs (claude.ai) with a painted shell but no mounted content. Skipped targets register `CONSTRUCTOR_TARGET_NOT_HOOKABLE`. Detection is preserved: the affected detectors still fire via their `*.prototype.*` method hooks (`Intl.DateTimeFormat.prototype.resolvedOptions`, `EventTarget.prototype.addEventListener`) plus their `window`/`content` signals. Accessor/data `window.*` props (`devicePixelRatio`, `innerHeight`, `speechSynthesis`) are unaffected.
  - **Removed dead `eventReceivedTime`** variable in the install handler.
- **Codebase audit batch (correctness + hardening)** — From a whole-codebase audit with adversarial verification:
  - **Pattern-cache eviction** (`utils/pattern-cache.js`) — `Math.ceil(maxSize * 0.1)` → `Math.max(1, Math.floor(maxSize * 0.1))` so eviction never over-evicts and always drops at least one entry.
  - **Robust context-invalidation check** (`utils/utils.js`) — replaced the brittle `error.message.includes('Cannot read properties of undefined')` with `error instanceof TypeError && /Cannot read|undefined|invalid/.test(error.message)`, reducing spurious error logs.
  - **Listener idempotency guards** — added `listenersAttached`-style guards to `sections/detection/detection.js` (`setupEventListeners`, `setupMessageListeners`), `sections/history/history.js` (`registerSettingsListener`), and `sections/settings/settings-ui.js` (`setupEventListeners`) so revisiting popup tabs can't double-attach handlers.
  - **History timestamp escaping** (`sections/history/history.js`) — `timeAgo`/`fullDate` now run through `FormatUtils.escapeHtml` in the `innerHTML` template, matching the file's existing escaping.
  - **Window-condition fallback drift fixed** — the hardcoded fallback lists in `sections/rules/rules-condition-ui.js` and `sections/rules/helpers/helper-window.js` now mirror the canonical `PRESET_GROUPS` in `window-condition-language.js` exactly (added `typeof symbol/bigint`, `has length`, `!== 0`; removed non-canonical `not undefined`/`not null`). Fallbacks kept for load-order safety.
  - **Install-debounce moved to config** — the hardcoded `250` ms hook install-debounce in `content-main-world.js` is now `DEFAULT_HOOKS_CONFIG.INSTALL_DEBOUNCE_MS` (clamped via `buildHooksConfig`). Expected-unavailable API list hoisted to a named `EXPECTED_UNAVAILABLE_APIS` const.
  - **DataDome PHP export `ReferenceError`** (`datadome-advanced-actions.js`) — the PHP parsing-code template interpolated a nonexistent JS var `$urls` instead of `urls`, throwing whenever the PHP export was generated. Fixed.
  - **Imperva analysis success notification never showed** (`imperva-advanced-ui.js`) — `displayAnalysisResults` referenced an undefined `scripts` var for the count (`ReferenceError`), making the success notification unreachable. Now uses `impervaScripts.length`.
  - **"Analyzing…" state now appears instantly on popup open** (`popup.js`, `sections/detection/detection.js`) — the detection tab left the body blank while `checkAndDisplayExistingDetection` awaited `tabs.query` → `storage` → blacklist check → a `GET_DETECTION_DATA` service-worker round-trip before rendering any state; on a cold service worker that gap showed as an empty panel. The popup now optimistically renders the analyzing state the moment the tab opens (unless results are already shown), and the real state replaces it once the lookup settles (all terminal states call `hideLoadingState`). Also removed an over-eager `listenersAttached` guard on `Detection.setupEventListeners` that could skip re-binding after `loadHTML` rebuilds the tab's DOM.
  - **Detector logo icons normalized & restyled** (`detectors/icons/`) — official logos were inconsistent sizes (akamai/hcaptcha/reblaze 64×64, aws 144×144) and `shape_security_official.png` was actually a WebP file with a `.png` extension. First normalized all to real 48×48 PNGs, then restyled every official logo onto a **uniform white rounded-square tile** so they render consistently on the dark popup. Replaced blurry wordmark/pixelated icons with **crisp brand marks** sourced from simple-icons (Cloudflare cloud, Akamai) and high-res favicons (AWS, Imperva, Arkose/FunCaptcha, Sucuri, Reblaze, DataDome, PerimeterX/HUMAN); kept the already-clean ones (reCAPTCHA, hCaptcha, GeeTest, F5). Filenames unchanged, so detector `icon` references still resolve. Shape Security uses the **F5 logo** (it's an F5 company); Reblaze (no usable symbol) uses a clean bold "R" monogram tile; the FunCaptcha/Arkose mark was recolored green. (PerimeterX is lower-res — only a 32px favicon exists.)
  - **Color settings rows misaligned** (`modules/styles/settings.css`) — the badge (insignias) rows used a `flex:1` text label that pushed the swatch+hex to the right, while category and tag rows used fixed-width pills, so their swatch/hex columns sat further left. Added `margin-left: auto` to `.color-row .color-picker-container` so all three sections (insignias, categoría, etiquetas) right-align the swatch + hex into the same columns.

### Removed

Verified every consumer loads these from the popup or background (never a content script or web page), so the entire block was removed. (`manifest.json`)
- **46 unused locale keys × 12 locales = 552 dead translation entries** — Surfaced by the new `node scripts/check-locale-keys.js --unused` audit, then verified safe to drop by confirming the codebase has **zero dynamic i18n-key construction** (no `prefix${x}`/concatenated keys anywhere; the only "dynamic" lookups go through literal maps like `difficultyKeyByValue`, which substring-match fine). Removed families: `analysisStep*` (12 — `createAnalysisSteps()` uses hardcoded English and its render is a no-op), `copyOverview*` (11 — referenced nowhere), `tagColor*` (8 — superseded by `methodLabel*`), `detectionBadge*Clear` (3), plus singletons (`colorCustomization`, `tagColorsHeading`, `enableDetection`, `detectionIsOff`, `settingsLanguageLabel`, …). Each locale dropped from 595 → 549 keys; parity preserved.
- **94 unused locale keys × 12 locales = 1,128 dead translation entries** — Grep-audited every key in `_locales/en/messages.json` against all JS/HTML/JSON/CSS files outside `_locales/` and `CHANGELOG.md`. Verified there is exactly one dynamic-key construction site in the codebase (`difficulty${X}` in `detection-ui.js`) and that the unused list does not overlap with it. Dropped keys included orphaned aria-labels (`actionClearCacheAria`, `actionCopyOverviewAria`, …), obsolete history-item action labels (`historyItemActionClearCache`, …), unused rule-editor helpers (`ruleContentSearchScope`, `helperWindowConditionExamples`, …), and never-shipped JS-API event labels (`evtExtensionLoaded`, `evtDetectionStarted`, …). - **`DetectorManager.precompileDetectorPatterns` + `cleanPrecompiledPatterns` (137 lines)** — Both methods wrote to `pattern._compiledRegex` / `_compiledNameRegex` / `_compiledValueRegex` properties that **no other code in the codebase ever reads**. The two methods plus their two call sites in `loadDetectorFile()` were therefore wasting CPU on every detector load and every reload without producing any consumed value. ### New Features
- **Upload detections to a shareable paste** — New leftmost button in the detection overview action row uploads the current detections to a keyless, **unlisted** paste (dpaste.com — no API key, link-only) and copies the URL to the clipboard + opens it in a new tab. The paste body is the Scrapfly banner followed by pretty-printed JSON:

  ```
  ============================================
  Made by Scrapfly.io
  ============================================

  { "source": "Scrapfly.io", "url": …, "summary": { "detections": …, "confidence": …, "difficulty": … }, "detections": [ … ] }
  ```

  Pastebin itself was not usable — its API mandates a developer key for every paste, which can't be committed to a public repo; dpaste.com's v2 API allows anonymous unlisted pastes with a 30-day expiry. The `fetch` runs from the popup (allowed by the existing `https://*/*` host permission + `connect-src https:` CSP — no manifest change). Files: `sections/detection/detection.html`, `sections/detection/detection-actions.js` (`uploadDetectionsToPaste` + `buildDetectionsPasteContent`), `sections/detection/detection.js` (wrapper + listener), `modules/styles/detection.css`, `_locales/*` (4 new keys).
- **Locale + structure CI guards** — `scripts/check-locale-keys.js` gained an `--unused` mode (substring-scans the whole source corpus and fails on any canonical key referenced nowhere). Added `scripts/check-structure.js`: validates `<div>`/`<button>` tag balance in `popup.html` + every section template, JSON validity across all `_locales` and `detectors` files, and hard-fails on the modal-header anti-pattern (any `close-btn`/`modal-close` rule using `position: absolute`, which is what let header text slide under the X). Both run with plain `node`, no deps.
- **Color customization split into separate Category and Tag cards** — The single paginated "Color Customization" card (1/4: category colors on page 1, tag colors on pages 2–4) is now two distinct cards in Settings → General: a static **Category Colors** card (Anti-bot / Captcha / Fingerprint) and a paginated **Tag Colors** card (1/3) for the eight tag colors. New `tagColors` i18n key added to all 12 locales (derived from each locale's existing `tagColorsHeading`). (`sections/settings/settings.html`, `_locales/*/messages.json`)
- **Language selector in Settings → General** — Added a Language card with a `<select>` letting the user override the extension UI language independently of the browser locale. Options cover all 12 supported locales with flag emoji + native name (🇺🇸 English, 🇪🇸 Español, 🇧🇷 Português (Brasil), 🇫🇷 Français, 🇩🇪 Deutsch, 🇮🇹 Italiano, 🇷🇺 Русский, 🇯🇵 日本語, 🇰🇷 한국어, 🇨🇳 简体中文, 🇸🇦 العربية, 🇮🇳 हिन्दी) plus a "🌐 Use browser language" default. Selection is persisted to `chrome.storage.local` under `scrapfly_language_override` and applied immediately on change via a re-`I18n.apply(document)` pass. Backed by a new `I18n.loadOverride(locale)` method that fetches `_locales/${locale}/messages.json` and short-circuits `I18n.get()` to read from it before falling back to `chrome.i18n.getMessage`. On popup boot, `DOMContentLoaded` now awaits the override fetch (~1–3ms) before calling `startAutoApply` so the first render is in the chosen locale.

### Fixes
- **Detection paste upload hardened (data leak + safety)** — Following a security review, the new upload feature no longer puts raw cookie/header **values** (live `__cf_bm` / datadome session tokens) or the URL **query string** into the paste — it emits only method counts + origin/path. The URL returned by the paste service is pinned to `https://dpaste.com/` before `chrome.tabs.create` opens it (no longer opens an arbitrary network-returned URL). The `fetch` now sets `credentials: 'omit'`, `redirect: 'error'`, `referrerPolicy: 'no-referrer'` (matching the webhook path). A confirmation dialog now states the paste is publicly readable before uploading, and the content build moved inside the `try` so a serialization throw surfaces as an error toast instead of an unhandled rejection. (`sections/detection/detection-actions.js`)
- **Blacklist add/remove could silently wipe ALL settings** — On a `JSON.parse(scrapfly_settings)` failure, `addToBlacklist`/`removeFromBlacklist` fell back to `settings = {}` and then `storage.set` persisted it — overwriting webhook config, colors, cache settings, everything, with the parse error hidden behind `debugMode`. Both now log unconditionally and **abort** (with a toast) instead of writing. (`sections/detection/detection-actions.js`)
- **Production errors no longer swallowed (`debugMode`-gated logging)** — Removed the `if (this.debugMode)` guard from 19 `Logger.error` catch sites across `detection-actions.js` / `detection-requests.js` / `detection.js`, including the central `processDetectionData` path that rendered "nothing detected" when processing actually **threw**. The constructor's empty storage `.catch` and the disabled-state blacklist-remove handler now log (and the latter notifies the user). `Logger.error` is designed to always log; the guard defeated it.
- **Background unhandled rejections silently destabilizing the service worker** — Wrapped all four `webRequest` listeners (`background/header-capture.js`) in a logging helper, the `REQUEST_DETECTION` async IIFE (`messages-detection.js` — a throw there previously left the popup's message channel open forever with no diagnostic; it now calls `sendResponse({status:'error'})`), and the startup IIFE (`init.js`) in a `.catch`. Service-worker rejections are dropped silently by Chrome, so these were invisible.
- **Empty catches dropping signal** — `HOOK_FAILURE_REPORT` / `SCRAPFLY_DEBUG_LOG` settings-read failures (`messages-logging.js`) and `UpdateManager.getIncompatibleUpdates`/`…Count` storage failures (`update-manager.js`) now log a warning instead of discarding silently — the latter no longer reports "0 incompatible updates" when the storage read actually failed.
- **`innerHTML` injection sinks for user-created rule values** — Detector name, category badge text, custom-icon `src`, and emoji icon are now escaped before insertion in `detection-ui.js`. Added `FormatUtils.escapeAttr` for attribute context (`escapeHtml` does not escape quotes, so it was unsafe for `src`/`alt`). The category badge no longer interpolates an unvalidated color into its inline `style`. (CSP already blocked script execution; this closes DOM/CSS-injection and quote-breakout.)
- **Webhook custom header names sanitized** — Stripped characters outside the RFC 7230 token set (incl. CR/LF) from webhook header names so a malformed name can't smuggle control characters or throw an opaque fetch `TypeError`. (`sections/settings/settings-runtime.js`)
- **Settings modal close "X" overlapped by header text in translated/RTL locales** — The settings header rendered the subtitle (`Configure your extension preferences`) as a full-width sibling of a `position: absolute` close button, so any locale with a longer string (Spanish, German) — and Arabic — ran the subtitle underneath the X, clipping it. Restructured the header to the same flex `space-between` pattern every other modal already uses: the subtitle now lives inside `.header-content` (a `flex: 1; min-width: 0` column) and `.close-btn` is a normal `flex-shrink: 0` sibling that always reserves its corner slot. The X no longer collides with header text in any language. (`sections/settings/settings.html`, `modules/styles/settings.css`)
- **Rule-modal close "X" had the same latent overlap risk** — `.rule-modal-close` (shared by all 13 rule editor/helper modals) was `position: absolute` with the title reserving space via a hand-tuned `padding-right: 44px`, so a longer translated title could slide under the X. Converted the shared rule to the canonical flex-sibling pattern (`flex-shrink: 0` button; title is `flex: 1; min-width: 0` with `overflow-wrap`), fixing all 13 modals uniformly. Surfaced by the new `check-structure.js` guard. (`modules/styles/rules.css`)
- **Color-pagination total page count was a hardcoded HTML literal** — `setupColorPagination()` read the page count from `.color-page` elements but never wrote `#colorTotalPages`, so the displayed total was a static string that had to be hand-edited whenever a page was added/removed (it briefly read `4` after the Tag card dropped to 3 pages). The JS now sets `totalPages.textContent = total`, making it the single source of truth. (`sections/settings/settings-ui-colors.js`)
- **`Deprecated API for given entry type` on Gmail and other sites** — The `Performance.prototype.getEntriesByType` hook proxied every call through `Reflect.apply`, so Chrome attributed observer-only entry types (`longtask`, `layout-shift`, `largest-contentful-paint`, `event`, `element`) to `content-main-world.js`. Those types are unsupported by `getEntriesByType` (native returns `[]` but logs a deprecation). The wrapper now short-circuits to `[]` without invoking the native API for those types, preserving semantics and silencing the console warning.
- **`this._lt_handleResponse is not a function` on detection timeout** — The detection-ui split added `_lt_handleResponse` as a `DetectionUI` helper but no `Detection.prototype` wrapper, so the loading-timeout path's `this._lt_handleResponse(...)` (where `this` is the `Detection` instance) was undefined. Now calls `DetectionUI._lt_handleResponse.call(this, ...)`.
- **`Identifier 'X' has already been declared` flood (content scripts re-injected)** — `requestDetection` re-injected the ISOLATED-world bundle (`logger.js` … `content.js`) that `manifest.json` already loads at `document_start`, re-running every top-level `class`/`const` and flooding the page console with `Uncaught SyntaxError: Identifier 'X' has already been declared` (`Constants`, `Utils`, `StorageManager`, `DetectionEngineManager`, `SettingsRuntime`, `hookBatcher`, …). No `window.*` presence probe can prevent it: re-injection RACES the manifest's own document_start injection on fresh loads and COLLIDES with lingering lexical bindings on orphaned tabs (extension reloaded with the tab still open). Wrapping each `executeScript` in try/catch doesn't help either — the `SyntaxError` is uncaught in the PAGE world, not in the background promise, so it floods regardless (and `executeScript` against a since-closed tab throws `No tab with id …`). Fix: **removed the programmatic injection entirely.** The manifest guarantees the bundle on every http/https page, so a non-responsive `GET_DETECTION_STATUS` ping just means the tab needs a reload — `requestDetection` now returns `{ status: 'needs_reload' }` instead of injecting. Popup `requestFreshDetection` ignores the status and falls back to fetching cached data, so the change is safe.
- **Badge shows count but popup empty (definitive)** — Popup open ran `GET_DETECTION_DATA` with a layered URL hash lookup that could miss valid `scrapfly_detection_storage` entries (SW restart dropped in-memory `tabLastDetection`, legacy expiry-in-seconds treated entries as expired, or hash/scope drift). ### Security
- **Cookie and header values no longer persisted in detection cache** — `detection-engine-manager.js` was storing `match.value = "${name}=${value}"` for cookies and `"${headerName}: ${headerValue}"` for headers. Detection cache lives in `chrome.storage.local` for up to 12h, meaning session cookies (`_session`, `auth`, `token`) and authentication headers (`Authorization: Bearer …`, `X-Api-Key: …`) were sitting on disk in plaintext readable by any other extension with `storage` permission. `match.value` now stores only the name; all UI fallbacks (`history.js`, `detection-ui.js`) already chain `match.value || match.name` so the display is unchanged.
- **Webhook SSRF + plaintext URL logging** — `SettingsRuntime.sendWebhookIfEnabled` accepted any URL the user typed into the settings input, including `http://169.254.169.254/`, `http://10.x.x.x/`, `file://`, etc., enabling SSRF from the background service worker. Added `_isWebhookUrlSafe()` which requires `https:` and rejects `127/8`, `10/8`, `172.16/12`, `192.168/16`, `169.254/16`, IPv6 loopback/link-local/ULA, and the `localhost` literal. Added `redirect: 'error'`, `credentials: 'omit'`, `referrerPolicy: 'no-referrer'` to the fetch options. Also added `_redactUrlForLog()` that strips query strings (which can carry auth tokens in webhook URLs) before logging, and removed full-header logging from the request line.
- **Tightened extension CSP beyond the MV3 defaults** — `manifest.json` `extension_pages` policy expanded from `script-src 'self'; object-src 'self'` to also enforce `img-src 'self' data: https:` (blocks data-exfil via injected `<img src=http://attacker/…>`), `connect-src 'self' https:` (blocks fetch/XHR to non-HTTPS hosts), `frame-src 'none'`, `base-uri 'none'`, and `form-action 'none'`. Inline `style="…"` attributes were preserved (~239 across HTML files) by leaving `style-src` unrestricted.
- **ReDoS guard bypass in URL pattern matching** — `demMatchPatternWithCapture` (`detection-engine-matching.js`) constructed `new RegExp(patternToMatch, flags)` directly, bypassing both `isLikelyEvilRegex` and `PatternCache` that `demMatchPattern` correctly used. A detector JSON with a catastrophic-backtracking URL/text regex would hang the service worker per page load. Now routed through `PatternCache.getCompiledPattern({ regex: true, caseSensitive })` for both the `regex` and `wholeWord` branches, which run the heuristic guard and return `null` on rejection. Switched the match invocation from a g-flag-stateful regex method to `String.prototype.match()` so cached regexes can be reused safely across calls.
- **XSS via unescaped page-controlled HTML in History/Detection/Akamai UI** — `tab.title`, `tab.url`, detector name, sensor data, and rule-helper keyword inputs were interpolated raw into `innerHTML` template literals at multiple call sites (`history.js:153,155,303,361,369,1010,1026`, `detection-ui.js:757`, `akamai-advanced-ui.js:663,684`, `pattern-helpers.js:74,203,272`). A malicious page setting `<title><img src=x onerror=…>` would execute the payload at the extension origin where all `chrome.*` APIs are available. All interpolations are now wrapped in `FormatUtils.escapeHtml()` (or `AdvancedUtils.escapeHtml()` for textarea contexts).
- **Missing `event.source === window` check on content.js postMessage listener** — `content.js:605` accepted any incoming `message` event, letting iframes (or another extension's MAIN-world content script) forge `WINDOW_DETECTIONS` / `HOOK_FAILURE_REPORT` / `SCRAPFLY_LOG` messages and pipe them into the background service worker. Added `if (event.source !== window) return;` as the first line of the handler.
- **ReDoS guard on user-supplied detector regex** — `PatternCache.getCompiledPattern` now rejects regex patterns that look catastrophically backtracking-prone (nested unbounded quantifiers like `(a+)+`, `(a{2,})+`, or patterns over 1000 chars). Heuristic is conservative — over-rejection is preferred to a frozen extension when a malicious or sloppy detector JSON is imported. Logs `Logger.warn` on reject.
